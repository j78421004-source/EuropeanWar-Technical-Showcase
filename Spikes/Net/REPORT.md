# Сетевой спайк: FishNet vs Netcode for GameObjects

> **Итог.** Берём **FishNet 4.7.4** (D-026). На одной и той же сцене он передаёт в 2,2–2,8 раза меньше трафика, показывает чужих бойцов точнее и с меньшей задержкой, а на плохой сети хост отклонил 8 % попаданий игрока против 47 % у NGO. Минус FishNet — подтверждение попадания приходит позже (RPC уходят пачками по тику); это закрываем мгновенным эффектом попадания у стрелка.

## Что проверяли

- Одна сцена на двух библиотеках: FishNet 4.7.4 и NGO 2.13.3 (Unity Transport 2.7.4), Unity 6000.3.28f1, тикрейт 30.
- Хост + клиент: 2 игрока (бегают и стреляют автоматически) + 20 ИИ-ботов (10 на 10). Боты стреляют, гибнут и возрождаются; всё считает хост.
- Игрок стреляет по боту на своём экране и шлёт хосту «я попал» с позицией цели. Хост сверяет её со своей позицией бота: расхождение больше 1,5 м — попадание отклоняется.
- Между клиентом и хостом — UDP-прокси `tools/net_proxy.py` с задержкой, джиттером и потерями.
- Прогон — 45 секунд, настройки библиотек по умолчанию, оба процесса на одном ПК.

- **Подтверждение попадания** — от «я попал» у клиента до ответа хоста.
- **Расхождение с хостом** — насколько бот на экране клиента в тот же момент стоит не там, где он у хоста. Именно оно решает, примет ли хост попадание.
- **Отставание картинки** — на сколько миллисекунд картинка клиента отстаёт от хоста; **остаток** — что остаётся после учёта этого отставания (насколько плавно и точно идёт интерполяция).
- Шрифтом выделен лучший результат в паре.

## Выводы

1. **Трафик.** FishNet стабильно ~50 кбит/с к клиенту при любой сети; NGO — 111–142 кбит/с, а на 100 мс пик доходит до 212 кбит/с. Для боя 30 на 30 (втрое больше бойцов) ориентировочно ~150 против 330–420 кбит/с [Допущение] — терпимо для обоих, но у FishNet запас больше.
2. **Точность.** У FishNet картинка отстаёт меньше на 60–85 мс, остаток после учёта отставания меньше в 2,8–14 раз (p95). На плохой сети NGO почти в половине случаев показывает бота дальше 1,5 м от настоящей позиции — для шутера это «я же попал!».
3. **Подтверждение попадания** у NGO быстрее: RPC уходят сразу, у FishNet — пачкой на тике. Решение для игры: эффект попадания (кровь, звук, маркер) показываем у стрелка сразу, ответ хоста нужен только для урона.
4. **Стабильность.** Ни одной ошибки в логах, ни одного зависания или отвала клиента на обеих библиотеках.
5. **Сложность кода** почти одинаковая: FishNet — 480 строк игрового кода + 127 строк сборщика сцены, NGO — 471 + 132, общий код — 433 строки.

## Подводные камни

**FishNet 4.7.4**
- Пакет из git не компилируется: транспорт Yak недописан. Решение — пакет встроен в `Packages`, папка Yak удалена (`tools/fish_fix.py`).
- `ServerManager._startOnHeadless` по умолчанию true: в batch-режиме сервер стартует сам. Сборщик выключает.
- Игрока при подключении надо добавить в сцену (`AddOwnerToDefaultScene`), иначе он не видит объекты.
- `SyncVar` должны быть `readonly`, префабы — в `SinglePrefabObjects`.

**NGO 2.13.3**
- Имя RPC обязано заканчиваться на `Rpc`.
- `GlobalObjectIdHash` префаба ставится в `OnValidate`; при сборке из batch — через рефлексию.
- `OnDestroy` у `NetworkBehaviour` — только `public override` с вызовом базового.
- NGO 3.x требует Unity 6000.7, поэтому 2.13.3.
- FishNet и NGO в одном проекте конфликтуют (ILPP), спайки — в разных проектах.

**Замеры**
- `Stopwatch` в плеере Unity считает от старта процесса — время хоста и клиента не сравнить. Общие часы — `QueryPerformanceCounter` из kernel32.
- Запуск по таймерам ненадёжен (плеер стартует 1–16 с). Клиент запускается, когда хост занял UDP-порт 7777; остановка — по флаг-файлам.

## Как повторить

- Сборка: `tools/build_one.ps1 -Name NetFish -Src <папка fish>` (так же NetNgo). Проекты спайков: `D:/GameDev/Spikes/NetFish`, `D:/GameDev/Spikes/NetNgo` (в git не входят).
- Все 6 прогонов: `tools/run_all.ps1`; один: `tools/run_net8.ps1 -Lib fish -Scenario lan -Seconds 45`. Скрипты ждут раскладку `D:/GameDev/_agents/step8` и пишут в `D:/GameDev/_logs/net8`.
- Вручную: `Spike.exe` без аргументов — меню Host/Join, можно сыграть вдвоём по локалке.

## Ограничения

- Один ПК, по одному прогону на сценарий, 45 секунд.
- Настройки по умолчанию. NGO после настройки `NetworkTransform` (пороги, half-float, буфер интерполяции) может стать ближе [Проверить].
- Нет Steam-транспорта и настоящего интернета — это в M4.

## Файлы

- `common/`, `fish/`, `ngo/` — код спайка (общий и для каждой библиотеки, с редакторными сборщиками сцен).
- `tools/` — прокси, анализ, диагностика и скрипты запуска.
- `results/` — `summary.txt`, `run_status.txt`, по каждому прогону `analyze.txt`, `diag.txt`, `proxy.json`.
